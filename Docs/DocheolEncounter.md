# 환조 · 첫 보스 도철

이 복제본은 Unity 6000.3.23f1에서 실행하는 Windows 보스전입니다. 시작 씬은 `Assets/BossFight/Scenes/DocheolArena.unity`입니다.

## 원본과 구현 판단

원본 SampleScene의 Warrior 계층, 스프라이트, Animator와 CourseContent 이동·공격을 재사용합니다. 기존 배경은 새 씬에 가져오지 않았습니다. 새 아레나는 바닥·벽·고정 카메라로 구성합니다.

전달된 도철 자료의 거대한 입과 이빨, 나무 양뿔, 두 앞발, 뒷다리 없는 뿌리 하체를 반영했습니다. DT05의 뿌리 성장 → 전신 상승 → 체공 → 전신 낙하가 핵심 동작입니다. 아래 전투 수치와 2페이즈 연결 공격은 이 작업에서 정한 조정값이며 Notion에서 확정된 원안 수치로 주장하지 않습니다. DT04 흡입은 이번 구현에 포함하지 않았습니다.

| 동작 | 예고 | 활성 | 회복 | 회피 |
|---|---:|---:|---:|---|
| DT01 앞발 내려찍기 | 1.25초 | 0.22초 | 2.65초 | 앞발의 고정된 바닥 범위 밖으로 이동 |
| DT02 낮은 쓸기 | 1.05초 | 0.66초 | 2.65초 | 파동이 다가올 때 점프 |
| DT03 큰 물기 | 1.55초 | 0.22초 | 2.65초 | 입에서 거리를 벌리거나 뒤로 이동 |
| DT05 전신 낙하 | 1.90초 | 0.58초 | 3.00초 | 고정된 착지 영역 밖으로 이동 |

보스 체력 40, 플레이어 체력 8, 공격당 피해 1입니다. 플레이어 피격 무적 0.8초·경직 0.22초이며 대시 자체에는 무적이 없습니다. 대시는 속도 11, 지속 0.28초, 시작 기준 재사용 간격 0.4초입니다. 원소 해금·폼 체인지·퀵 스왑 없이 클리어할 수 있습니다.

체력 절반 이하에서 현재 회복 동작을 마친 뒤 2.1초 전환을 거쳐 2페이즈로 넘어갑니다. 이후 DT01 뒤에는 새 1.2초 예고를 가진 DT02가 연결됩니다. 연계가 끝나면 정상 회복 시간이 주어집니다. 표식·방향·목표는 공격 예고 시 고정됩니다. 회복 중에는 보스 위치와 방향이 고정됩니다.

보스 접촉 자체의 피해는 없습니다. 앞발과 입의 hurtbox가 공격 대상이며, 부상 중과 페이즈 전환에는 피해를 받지 않습니다. 같은 공격 ID는 상승·낙하·착지를 포함하여 플레이어에게 한 번만 적용됩니다. DT05는 50Hz FixedUpdate의 이산 판정이며 continuous swept collision으로 설명하지 않습니다.

## 구성

- Runtime: 전투 시작, 일시정지, 결과, 재도전과 한글 HUD.
- Combat: 보스 패턴, 명시적 공격 판정, 고정된 바닥 표식과 뿌리 파동.
- Player: 원본 플레이어를 새 전투에 연결하는 opt-in adapter.
- Presentation: 몸통·구강·턱·앞발 두 개·뿌리의 관절 리그, 접지 그림자, 입자, 제한된 카메라 진동과 합성 효과음.
- Editor: 원본 플레이어를 복제하는 씬 생성기, Windows 빌드, 로컬 MCP 연결 및 관찰 후 입력하는 Playtest 메뉴.
- QA: 명시적으로 `-bossqa`를 지정한 경우에만 실행되는 검증 도구.

## 개발과 복구

`Tools/Boss Fight/Build Docheol Arena`로 씬을 다시 생성할 수 있습니다. 이 명령은 새 도철 씬을 재생성하므로 그 씬에서 수동으로 바꾼 내용이 있으면 먼저 보존해야 합니다. 원본 SampleScene은 저장하지 않습니다. `Tools/Boss Fight/Build Windows Player`는 형제 폴더 Deliverables/Hwanjo_Docheol에 실행파일을 만듭니다.

원본 복구점은 `../RestorePoints/BeforeDocheol_20261003`이고 416개 파일의 SHA-256을 검증했습니다. 로컬 Git 원본 커밋은 `bac23a7affcf081f49777906d09b5c4e43ba6fd2`, 원본 브랜치는 `baseline/original-desktop`, 개발 브랜치는 `feature/docheol-boss-battle`입니다. 원격 저장소나 공개 배포는 생성하지 않았습니다.

## 도구·아트 출처

CoplayDev/unity-mcp v10.0.0을 commit `d49ae2953580f3481beb1e084a1da2682f0b5610`에 고정했습니다. 로컬 서버 주소는 127.0.0.1:8080이며 telemetry를 차단했습니다. 실제 MCP로 씬 생성, 씬·계층·콘솔 조회, 재생, 화면 캡처, Windows 빌드를 실행했습니다. 증거는 형제 QA 폴더의 mcp-live-evidence.json 및 Unity 로그에 있습니다. 게임 실행 자체에는 MCP, uv, Python 또는 인터넷 연결이 필요하지 않습니다.

DocheolAtlas.png는 사용자가 전달한 도철 원본 자료를 바탕으로 제공된 imagegen 도구에서 생성한 파츠 아틀라스입니다. 원본 이미지는 형제 Reference 폴더에 보존했습니다. atlas SHA-256: `781EA994E69511404EAAF1B9751BCEAEED204D60532F6E6EDC5CC9FD480CDABB`. Unity 리그는 원본 아틀라스를 바꾸지 않고 runtime에서 crop·관절 이동과 구강 연결 마스크를 적용합니다. 효과음은 코드로 합성했습니다. 별도 유료 API나 새 결제는 사용하지 않았습니다.

## 검증 범위

자동 검증은 실제 WindowsPlayer에서 수행합니다. 계약·강제 패턴 검사는 합성 피해나 패턴 강제를 사용한 항목을 보고서에 표시합니다. victory와 defeat 검사는 일반 입력 경로만 사용하며 체력이나 피해를 조작하지 않습니다. Editor Playtest는 화면 관찰 후 사람이 아닌 에이전트가 입력을 선택하고 짧은 시뮬레이션 구간을 진행하는 방식입니다. 실제 키보드 수동 플레이테스트와 구분합니다.

수치 결과, 빌드 SHA와 최종 검증 요약은 형제 QA 폴더의 최종 보고서를 참조하세요. `captures-patterns`의 일부 recovery 파일은 비동기 캡처 시 다음 강제 패턴으로 넘어갈 수 있으므로 정밀 상태 증거는 JSON, 시각 증거는 자연 전투 캡처를 우선합니다.
